# 00 · 概述（Overview）

> 本文件是 Overlay 文件格式规范（`SPEC/`）的总纲与阅读入口。
> 它给出术语、设计目标与文档目录，但**不含规范性（normative）字节定义**——所有字节级、行为级约束都在对应章节文档中。

- 规范名称：**Overlay File Format Specification**
- 版本：v1.0（见 `06-versioning.md`）
- 定位：语言无关的**文件格式 + 生成流程 + 运行时行为**规范。
- 参考来源：`spec.md`（设计白皮书）。本目录把白皮书的“设计意图”固化为**可校验、可实现、可互操作**的规范。
- 配套：`SPEC/README.md`（本目录的阅读顺序与文档地图）。

## 1. 什么是 Overlay

把一个预先编译好的、固定不变的原生可执行程序（**Stub**），与用户指定的任意文件集合（**Payload**），合成为**一个可分发的单一可执行文件**。运行时，Stub 从自身文件尾部读取 Payload，按业务逻辑使用其中的数据。

Overlay 的本质是**附加数据（Appended Data / Overlay）**：操作系统的可执行文件加载器只关心文件开头的可执行格式部分（PE / ELF / Mach-O），尾部多出来的字节被忽略。于是把数据直接追加在 Stub 后面，由 Stub 自己在运行时读取自身文件的尾部。

### 与自解压程序（SFX）的区别

| 维度 | SFX（如 7-Zip SFX、makeself） | Overlay |
|:---|:---|:---|
| Stub 来源 | 通用解压器 | **自定义的固定程序** |
| 运行时行为 | 解压到磁盘再运行 | **完全自定义** |
| 解压引擎 | 需要 | **不需要**，Stub 直接读取归档 |
| 生成逻辑 | 依赖外部工具 | **纯字节拼接** |
| 语言绑定 | 通常绑定特定工具 | **无绑定** |

## 3. 术语

| 术语 | 含义 |
|:---|:---|
| **Stub** | 预编译的、固定不变的原生可执行程序（ELF / PE / Mach-O）。 |
| **Payload** | 随分发而变的用户文件集合。 |
| **Archive** | Payload 打包后的字节流（TAR 或 Raw，见 `01-file-format.md`）。 |
| **Trailer** | 追加在文件末尾的元数据块，是 Stub 定位与读取 Archive 的依据。 |
| **Generator** | 把 Stub + Payload 合成为单个 Overlay 文件的程序。 |
| **Overlay 文件** | 最终产物：`Stub ‖ Archive ‖ Trailer` 的单文件。 |

## 4. 规范性关键词

本规范使用 RFC 2119 关键词：

- **MUST / 必须**：绝对要求。
- **MUST NOT / 禁止**：绝对禁止。
- **SHOULD / 应当**：有充分理由可偏离，但需说明。
- **MAY / 可以**：可选。

“字节小端序”等通用约定在 `01-file-format.md` 中集中声明，各节不再重复。
