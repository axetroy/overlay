# Overlay 规范 · 目录与阅读顺序

`SPEC/` 是 Overlay 文件格式的**权威规范**（语言无关）。它由设计白皮书 `spec.md` 提炼、细化而来，补齐了白皮书刻意留白（“不回答用什么写”）之外的**可校验、可实现、可互操作**部分。

## 阅读顺序

| 顺序 | 文件 | 一句话 |
|:---|:---|:---|
| 1 | `00-overview.md` | 总纲：是什么、术语、文档地图 |
| 2 | `01-file-format.md` | **字节级布局**：魔数、Trailer、Archive、压缩、校验和 |
| 3 | `02-generation.md` | **生成器流程**：如何把 Stub+Payload 合成单文件，确定性要求 |
| 4 | `03-runtime.md` | **运行时行为**：Stub 如何从自身尾部读取、定位算法、校验顺序 |
| 5 | `04-conformance.md` | **一致性判据**：测试向量、Pass/Fail、互操作、确定性 |
| 6 | `05-extensions.md` | **扩展机制**：flags、自定义压缩、兼容原则 |
| 7 | `06-versioning.md` | **版本策略**：主/次版本、不兼容变更、发布流程 |

## 与其他目录的关系

- `reference-impl/`：规范**允许**多语言参考实现，但本仓库当前只放规范与测试向量，**不绑定**任何一种语言。
- `test-vectors/` + `expected/`：`04-conformance.md` 定义的标准测试向量与预期解析结果，是互操作性的可执行证明。
- `docs/examples.md`：面向使用者的示例（如何用生成器/读取器），信息性，非规范。

## 关键词

规范性章节使用 RFC 2119（`MUST / SHOULD / MAY`）。凡带“MUST”的字节/行为即为可校验判据。
