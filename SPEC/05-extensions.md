# 05 · 扩展机制（Extensions）

> **规范性 + 信息性文档。** 本文件规定 Overlay 如何在不破坏既有实现的前提下扩展：`flags`、自定义 `compression`、新的 `archive_format`，以及向后兼容原则。
> 原则：**默认值永远对应 v1 基线；扩展位必须被旧实现安全忽略，或让旧实现明确报错，绝不产生“静默误读”。**

## 1. 兼容性总原则

- 扩展 MUST 保证：**旧读取器遇到新文件时，要么正确忽略扩展、要么明确报错**；二者都不允许“读错还不报错”。
- 用 `version`（`01-file-format.md` §3.1）做主版本门控：语义不兼容的变更 MUST 递增 `version`；旧 Stub 读到更高 `version` MUST 拒绝并提示升级。
- 用 `flags` 做同版本内的能力协商。

## 2. `flags`（u16，当前 MUST 为 0）

`flags` 是位域。v1 基线要求实现者**写入 0**；读取方 MUST 容忍并忽略未知位（前向兼容），但 SHOULD 记录“检测到未知 flag”。

### 2.1 预留位约定

| 位 | 含义（预留） | 状态 |
|:---|:---|:---|
| bit0 | 校验和算法选择（见 §3） | 预留，v1 默认 0 |
| bit1–15 | 未定义 | MUST 写 0；旧读取方 MUST 忽略 |

> 启用 `bit0` 表示“本文件的校验和不是默认 CRC-64/XZ，而是替代算法”；此时读取方 MUST 能识别并切换算法，否则 MUST 报错。

## 3. 校验和算法扩展

- 默认 **CRC-64/XZ**（`01-file-format.md` §6）——所有实现 MUST 支持。
- 替代算法（如 **SHA-256 前 8 字节**）**可以**被某实现采用，但 MUST：
  1. 通过 `flags` 的预留位标记；
  2. 在本文档登记该位与算法的映射；
  3. 让**未登记该扩展的读取方**能安全识别并报错（不得当作 CRC-64 解析）。
- 未登记的实现 MUST 使用 CRC-64/XZ，`flags` 相关位写 0。

## 4. 自定义 `compression == 3`

- 值 `3` 表示“实现自定义压缩”。
- 自定义算法 MUST 在**分发该 Overlay 文件时随附**可解码方法（如随附解码库 / 说明文档）；
- 未随附解码方法的自定义压缩，MUST NOT 作为可互操作分发物（它只适用于“生成方与读取方同一实现族”的内部场景）；
- 跨实现分发时，SHOULD 优先使用 `gzip(1)` 或 `zstd(2)`，二者为规范默认支持的互操作编码。

## 5. 新的 `archive_format`

- 当前仅 `0=TAR`、`1=Raw`。
- 新增格式值（如 `2=...`）属于**语义不兼容扩展**：MUST 递增 `version` 或在本文档登记并要求读取方显式声明支持；旧读取方 MUST 对未知 `archive_format` 报错，不得按默认 TAR 解析。

## 6. 向后兼容清单（实现者自查）

- [ ] 读旧版（v1）文件：新实现 MUST 能正确读取。
- [ ] 新实现写出带扩展位的文件：旧实现 MUST 能“忽略未知 flag / 拒绝未知 version / 报错未知 compression·format”。
- [ ] 默认路径（无扩展位）MUST 保持与 v1 字节级一致。
