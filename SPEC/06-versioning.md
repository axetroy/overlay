# 06 · 版本演进（Versioning）

> **信息性 + 规范性文档。** 规定 Overlay 规范本身的版本策略：`version` 字段语义、兼容/不兼容变更的分界、发布流程。

## 1. `version` 字段语义

- `version`（`01-file-format.md` §3.1，u16）标记该 Overlay 文件遵循的规范**主版本**。当前值 **1**。
- 取值规则：
  - **主版本（major）**：字节布局、字段语义、定位算法等发生**不兼容变更**时递增。
  - **次版本（patch）**：仅新增可选能力（如新的 `flags` 位、新的 `compression` 值）且旧实现可安全忽略/报错时，**不递增** `version`，通过 `05-extensions.md` 登记。

## 2. 什么算“不兼容变更”（MUST 递增主版本）

- 改写字段偏移、宽度、字节序；
- 改变 `magic`、定位算法、校验和覆盖范围；
- 改变 `archive_format` / `compression` 的现有取值语义；
- 让旧读取方“读错还不报错”的任何变更。

## 3. 什么算“兼容扩展”（不递增，登记即可）

- 新增 `flags` 预留位（§05-extensions）；
- 新增 `compression == 3` 的自定义编码（随附解码方法）；
- 新增 `archive_format` 值（旧方 MUST 报错，不静默误读）。

## 4. 发布流程

1. **变更提案**：在本仓库 `SPEC/` 修订相应章节，标注影响范围（兼容 / 不兼容）。
2. **定稿**：若涉及不兼容变更，分配新的主版本并更新 `00-overview.md` 的“版本”行。
3. **冻结**：为每个主版本产出一套 `test-vectors/`（见 `04-conformance.md`），作为该版本的互操作基准。
4. **废弃**：被取代的旧版本 SHOULD 在 `04-conformance.md` 标注 deprecated，但旧向量 MUST 仍可获取，以便旧实现继续验证。

## 6. 与 `flags` 的关系

- `version` 表达**格式主版本**；`flags` 表达**同版本内的能力开关**。
- 一条经验法则：**需要旧实现“认识”的变更 → 走 `version`；只需要旧实现“忽略或报错”的变更 → 走 `flags`。**
